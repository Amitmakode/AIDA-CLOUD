Concept · Step 01

The Client-Server Model

Client = the one who asks for something (your browser, phone app). Server = the one who has what's being asked for, and responds. Every interaction on the internet is a request → response cycle — nothing happens unless the client asks first.

Concept · Step 02

What A Website Really Is

A website is not magic — it's a set of files (HTML, CSS, JavaScript, images) stored on a server's disk. Same idea as Module 01: files sit in folders, located by paths — just now on someone else's computer, not yours.

Concept · Step 03

What An API Is — The Waiter Analogy

An API (Application Programming Interface) is a defined way for one piece of software to ask another for data or action — without needing to know how the other side works internally. The API defines the menu — what requests are allowed, and what comes back (usually JSON).

Concept · Step 04

DNS Basics: Name → Address

Every server has a numeric address, an IP address (e.g. 142.250.183.14). Nobody remembers numbers — so we use domain names instead. DNS (Domain Name System) is the internet's phonebook: it translates the name you type into the IP address your computer actually needs.

🧑
Type "google.com"
→
📖

Your browser doesn't magically "know" this — it asks a DNS resolver every time, which looks it up and returns the IP.
