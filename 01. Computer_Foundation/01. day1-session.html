Concept · Step 01

What Software Really Is

Software isn't magic — it's a very long, very precise list of instructions that the computer's hardware carries out, one step at a time.

Definition

Every app, game, website, and script you've ever used is a set of instructions written by someone, telling the hardware exactly what to do — move this data, show this pixel, add these numbers.

The CPU simply executes instructions without understanding their meaning — it has no awareness of what the numbers or letters actually represent. It just processes them, extremely fast and extremely literally.

Why This Matters To Us

  • When you write Python later, you are literally writing instructions
  • Bugs happen because the computer did exactly what you told it — not what you meant
  • "The computer is being difficult" — almost never; it's just following orders
  • Understanding this removes the fear of programming being some special talent
Concept · Step 02

Files, Folders, and Paths

Most persistent information on your computer is stored as a file, organized inside folders, and located using a path.

The Three Ideas

  • File — a single unit of stored data (a document, image, or script)
  • Folder (directory) — a container that groups related files together
  • Path — the exact "address" of a file, describing which folders you pass through to reach it

Note: not everything on a computer is a file — running processes, network connections, and system registries are managed separately by the OS, even though most of what you save and open is file-based.

path examples
# Windows-style path
C:\Users\Aditi\Documents\notes.txt
# Mac / Linux-style path
/Users/aditi/Documents/notes.txt
Concept · Step 03

What An Operating System Does

The OS is the manager sitting between you and the raw hardware — it decides who gets to use the CPU, memory, and storage, and when.

Core OS JobWhat It Actually Does For You
Manages filesCreates, reads, moves, and deletes files and folders on disk
Runs programsLoads software into memory and lets your CPU execute it
Handles hardwareTalks to your keyboard, mouse, screen, and network card via drivers
Manages users & permissionsDecides who can open, edit, or run what
Coordinates everythingAlso handles process scheduling, memory allocation, I/O, networking, and security behind the scenes
🪟 Windows — most common on personal/office machines 🍎 macOS — Apple's own OS, built on Unix 🐧 Linux — open-source, powers most servers
Concept · Step 04

What "Code" Actually Means

You write source code in a human-readable language — but the CPU only understands machine code. Something has to translate between the two, and different languages do it differently.

Compiler vs Interpreter

  • C / C++ — a compiler translates the full source code directly into machine code ahead of time, producing a standalone executable
  • Java — compiled to intermediate bytecode (.class), which the JVM then executes — not straight to machine code
  • Python — CPython first compiles your source into bytecode (.pyc) internally, which the Python Virtual Machine (PVM) then executes step by step
source_to_machine.py
# you write this ↓ (source code)
print("Hello, Data Science!")
# CPython compiles it to bytecode, then runs it
$ python hello.py
› Hello, Data Science!
Concept · Step 05

From Python Source To Output

Here's the full journey your .py file takes before you see any output on screen — every stage matters.

Each Stage, Explained

  • Source code — the plain-text .py file you write
  • Interpreter (CPython) — reads your source and compiles it internally
  • Bytecode — a compact, lower-level instruction set (not machine code yet)
  • Python Virtual Machine (PVM) — executes the bytecode instructions one by one
  • Operating System — grants the PVM access to memory and hardware
  • CPU — physically carries out the low-level operations

Concept · Step 06

Program, Executable, Process & RAM

Four words beginners mix up constantly — once these click, a lot of confusing computer-talk suddenly makes sense.

The Four Ideas

  • Program — the source code or instructions, sitting on disk, not yet running
  • Executable — a program packaged into a ready-to-run file the OS can launch directly
  • Process — a program that is currently running, loaded into memory with its own resources
  • RAM — the fast working memory where a running process's instructions and data live while the CPU works on them

Concept · Step 07

Everyday Analogies That Make It Click

If any of the last few ideas felt abstract, hold onto these — they map almost perfectly onto something you already understand.

Recipe = Code

A recipe is a precise, ordered list of steps: chop this, heat that, wait 10 minutes. Follow it exactly and you get a dish — skip a step or misread a quantity, and it goes wrong.

Source code works the same way: a precise, ordered set of steps the computer follows exactly, in order, every single time.

Kitchen = Operating System

The kitchen provides the stove, the counter space, the utensils, and the rules of the room — the recipe can't cook itself without it.

The OS is exactly this: it provides the CPU, memory, storage, and hardware access that your program (the recipe) needs in order to actually run.

Bonus → A running process is the dish actually being cooked right now; RAM is the counter space it's using while it cooks
Before The Demo

Tools We'll Use Today

Just two tools — both of which you already have installed. No setup needed, we're only looking today.

File Explorer / Finder

The built-in visual tool your OS gives you to browse files and folders — File Explorer on Windows, Finder on Mac.

We'll use it to actually see the folder tree, hidden files, and file extensions we just talked about.

VS Code (View Only)

A popular code editor. Today we're only opening it to look at what a code file actually contains — no writing or running code yet.

The file extension helps the OS decide which application should open a file — but the actual contents are what determine its real format.

Example: renaming virus.exe to virus.txt does not turn an executable into a harmless text file — only the label changes, not the content.
